# smart_hospital_agent v3.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把现有“可演示”的医疗 Agent 收口为真实可用的 v3.1：身份隔离、真 HITL、多轮会话、订单/报告生命周期、数据权利、证据原文和可回归测试全部落地。

**Architecture:** 保持 Next.js 静态前端 + FastAPI 单 Agent + PostgreSQL/pgvector + 本地医院 MCP。新增用户、消息、审核队列三张核心表；所有资源按 JWT `sub` 做归属校验；支付从“客户端 token”改为“患者申请 → 管理员审批 → 服务端调 MCP”；会话从单轮事件日志改为可恢复的多轮消息；医院 MCP 仍为本地适配器，但持久化、幂等、审核契约按真实系统标准实现。

**Tech Stack:** Python 3.12 / FastAPI / asyncpg / PostgreSQL 16 + pgvector / Next.js 16 静态导出 / Playwright / pytest / ruff / GitHub Actions

**Spec:** `docs/V3.1-ACCEPTANCE.md`

## Global Constraints

- 不重做前端；保留现有页面、视觉与信息架构，只补真实交互和数据恢复。
- 不引入多 Agent、Planner、CrewAI、LangGraph；保持单 Agent 循环 + 确定性策略。
- 不接真实医院 MCP（v3.2，需要院方凭据）；本轮把 mock 做成可替换、持久化、幂等的真实边界。
- 所有自动化测试使用 fake gateway / fake model server，不调用真实 LLM、Embedding、Rerank；生产 E2E 如涉真实模型，须先按 `/root/AGENTS.md` 确认 provider/model。
- OpenRouter 只用免费模型；本轮不新增任何模型 provider。
- 不在仓库、文档、前端构建产物中出现真实密码/token/JWT；`.env.example` 只留占位符。
- 所有新增表/字段使用幂等迁移（`CREATE TABLE IF NOT EXISTS`、`ALTER TABLE ... ADD COLUMN IF NOT EXISTS`）。
- 旧数据兼容：bootstrap 用户 `id` 继续使用 `admin` / `patient`，历史 `user_id` 不变。
- 所有新增查询必须带 `user_id` 归属条件；管理员接口必须同时经过入口鉴权与 `role=admin`。
- 每个任务结束必须跑对应测试并提交；不在任务之间夹带无关重构。

## 0. 假设与非目标

**假设**

- 部署仍是家服务器 API :8020 + 106 nginx 443 + 反向 SSH 隧道；单 uvicorn worker。
- PostgreSQL 容器 `sha_v2_db`、Redis 容器 `sha_v2_redis` 继续使用。
- 现有 `admin` / `patient` 账号迁移为 `users` 表记录；密码改为哈希存储。
- 医院 MCP 仍在本机 :9100，但订单/锁号写入 Postgres，重启不丢。
- 用户规模为个人/家庭到小机构试点，不做多租户。

**非目标**

- 真实医院 MCP、真实支付、医保、电子处方。
- 自注册、短信/邮箱验证、OAuth、多因素认证。
- 自规划 Agent、多智能体、长期记忆向量库。
- 药盒识别、陪诊、医生工作台、规则后台/evolution。
- 临床准确性盲测与大规模评测（另立 v3.2 计划）。

## 1. 数据模型变更

全部加在 `backend/app/db.py` 的 `SCHEMA` 与 `MIGRATIONS` 列表；启动时按顺序执行。现有 `init_schema()` 增加 `MIGRATIONS` 执行。

### 1.1 新表

```sql
CREATE TABLE IF NOT EXISTS users (
    id TEXT PRIMARY KEY,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,
    role TEXT NOT NULL DEFAULT 'patient' CHECK (role IN ('admin', 'patient')),
    enabled BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS messages (
    id BIGSERIAL PRIMARY KEY,
    session_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    member_id TEXT,
    role TEXT NOT NULL CHECK (role IN ('user', 'assistant')),
    content TEXT NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_messages_session ON messages (session_id, id);

CREATE TABLE IF NOT EXISTS review_requests (
    id TEXT PRIMARY KEY,
    kind TEXT NOT NULL CHECK (kind IN ('payment')),
    ref_id TEXT NOT NULL,
    user_id TEXT NOT NULL,
    member_id TEXT,
    status TEXT NOT NULL DEFAULT 'pending' CHECK (status IN ('pending', 'processing', 'approved', 'rejected', 'failed')),
    payload JSONB NOT NULL DEFAULT '{}'::jsonb,
    decision_note TEXT,
    decided_by TEXT,
    decided_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_reviews_status ON review_requests (status, created_at);
```

### 2.2 修改/废弃

- `POST /api/v1/auth/login`：查 `users` 表，校验哈希与 `enabled`；失败计数。
- `GET /api/v1/auth/me`：从 DB 返回 `{id, username, role}`。
- `POST /api/v1/chat/stream`：删除 `user_id` 字段；owner 校验 `session_id`；写 user/assistant 消息；按成员加载上下文。
- `POST /api/v1/booking/lock|orders`：删除 `patient_id` 入参；由服务端从 `member_id` 映射 `hospital_patient_id`。
- `POST /api/v1/booking/orders/{id}/pay`：患者调用返回 403/410；支付只能由审核批准触发。
- `GET /api/v1/followups`、`/home/summary`：增加 `member_id` 过滤。
- `GET /api/v1/reports`：增加 `has_image`；不再返回 `image_path`。
- 删除 `/api/v1/admin/rules*`、`/api/v1/evolution/*`、`/api/v1/doctor/consult`、`/api/v1/local/analyze`、`/api/v1/rag/search`（或保留为内部脚本，不暴露路由）。
- `/health` 保留为详细 readiness（含 DB/模型/MCP）；`/api/health` 为轻量 liveness。

| MCP 持久化与真实接口差异 | 中 | 保持工具 schema 不变；adapter 隔离 |
| 测试调用真实模型产生费用 | 高 | 全部 fake gateway；E2E 用 fake model server；生产 E2E 先确认 |
| 时间超期 | 中 | 范围冻结；M0/M1/M6 先交付止血价值 |
