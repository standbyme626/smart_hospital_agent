## 结论先行

项目已经不是“能不能跑”的问题，而是**产品承诺、临床安全、交易状态、数据合规、运维能力五条线都还没有达到真实患者可用的门槛**。最危险的共性是：

1. **前端承诺高于后端控制**：证据、人工复核、隐私、通知、退款，多处只有文案/半流程。
2. **临床安全层太薄**：危机识别靠关键词、DDI 只有 42 种药、报告解读无危急值、安全门禁不检查输出内容。
3. **交易状态机不完整**：锁号不互斥、支付不复核库存、订单不过期、支付后无取消/退款/改约。
4. **数据治理是演示级**：库/Redis 局域网裸奔、无外键/保留期、删除留 PHI、备份同盘明文。
5. **运维是单点演示拓扑**：单进程、单机、单隧道、监控假绿、迁移不可回滚。

## P1：核心业务/逻辑缺陷（按主题）

### 1. 临床决策
- 分诊可被最终报告静默降级/换科；`General Practice`/缺字段默认 normal/全科，UI 按 report 渲染 120/挂号（clinical P1-5）。
- 成员既往史被拼进当前主诉，既造成假危机，也把“皮疹+高血压”路由到心内科（clinical P1-6）。
- 多轮丢失结构化状态：只存 summary，不存 advice/meds/followup/citations；triage 只看最后 2 条；华法林→布洛芬的追问可能查成 `none`（clinical P1-8）。
- 危机脚本一套通吃：过敏性休克/低血糖仍说“不要自行服药”；自杀无热线；固定 0.95 置信度（clinical P2-13）。
- 报告/皮肤解读不带年龄性别病史，无危急值升级；`status` 未知/大写会显示绿色“正常”；客户端可控制 kind/MIME（clinical P1-9）。
- 规则分诊仍有顺序错误：药物流产→精准药剂科、孕妇胸痛→妇产科 normal、胸痛不升 urgent；LLM 给的合法别名在 normalize 前被丢弃（clinical P2-14）。

### 2. 模型/检索降级
- 主模型失败时静默降级到 0.6B 文本模型且无 tools，final 仍硬编码 `opencode-go`；报告/视觉也可能走文本模型（clinical P1-10）。
- Embedding 失败静默落 hash 向量，检索池可能永久混入不同向量空间；rerank 失败返回 1/(i+1) 假分数并展示给用户（clinical P1-11 / data-ops F-04）。
- 视觉/embedding/rerank 完全不记账；报告解读和 admin eval 无预算/配额；chat 配额可用并发或删成员绕过（data-ops F-03 / security P2-09）。

### 3. 挂号/支付/订单
- 未支付订单永不过期，可数月后支付过期号；已支付不能取消/改约/退款，号源永久占用；无 completed/no-show（booking F3/F4）。
- `processing` 审核在后台 UI 不可见，120s 恢复逻辑没有入口；患者/管理员均无通知/SLA；pending 列表上限 100（booking F5/F6 / frontend F7/F12）。
- 只恢复最新一单，历史已支付订单/指引不可见；新挂号不写健康时间线；9 条旧 booking 对 0 条 MCP 订单，孤儿订单查单/取消 502（booking F7/F8/F10）。
- `hospital_patient_id` 是本地随机 `HP-<member>`，无实名/证件/医院患者主索引；姓名改了医院侧不同步（booking F12）。
- 医生卡 30/40/50 元、号源/订单固定 50 元；审批不校验 MCP 返回的 `payment_status/paid_amount`，可能确认未支付（booking F13）。
- 取消在 DB 事务/行锁内调 20s MCP，10 并发可耗尽连接池（booking F15）；chat 的 cancel/order 工具绕过本地归属与状态（booking F10 / security P2-14）。
- 时区 UTC：配额每天 08:00 重置；随访按“支付日+7 天”而非就诊日，可能早于就诊（booking F11 / data-ops F-12）。

### 4. 前端/产品闭环
- 线上有 5 个会话、5 个订单、8 条时间线，但 UI 只能打开最新 1 个会话/1 个订单；`getSessions` 未使用（frontend F4/F8）。
- 时间线/最近记录不可点击；挂号事件从不写入健康时间线；报告/订单/会话无法从时间线回到现场（frontend F6）。
- 药管家没有提醒/依从记录，`reminder_times` 空转；只是药清单+DDI（frontend F5）。
- 接口失败被渲染成“还没有记录/0”，无错误/重试；错误 Toast 直接弹 `{"detail":...}` / `Failed to fetch`（frontend F9/F10）。
- 问诊向导状态不持久，去“我的/加家人”或刷新全丢；红旗“有/不确定”无阻断语义（frontend F1/F11）。
- 后台批准无二次确认、无号源时间/医生、无自动刷新/历史；移动端后台横向溢出 2717px（frontend F12/F14）。
- 文案超卖：“危机转人工”不存在、“每条建议都有来源”不保证、“图片仅用于本次”与持久化/第三方调用矛盾（frontend F13）。
- 无障碍：选中态仅颜色、无 `aria-pressed`、32px 触控目标、风险等级英文 `major/contraindicated`（frontend F15）。

### 5. 数据/评测/合规
- 527 条短文、5/21 科室 0 文档（精准药剂科/内分泌/普通外科/急诊/康复）；无逐文档来源/版本/许可；无相关度门槛；4096 维无法建 pgvector HNSW（>2000），当前全表扫（data-ops F-09 / clinical P0-3）。
- 评测自指：检索 in-corpus（n=30）、危机 in-sample（且 100/500 行空输入当 TN）；无 citation/vision/DDI/盲测/多轮评测，无 CI 门槛（clinical P2-15 / data-ops F-08）。
- 0 外键、无 TTL/保留期；一次问诊复制到 messages/events/health_events/audit_log；删除易漏表（data-ops F-06）。
- 无版本化迁移/回滚，启动吞异常仍健康；Kuma 浅健康；Prometheus 死目标；无 5xx/延迟/成本告警；备份明文同盘无异地/加密/失败告警（data-ops F-02/F-05/F-07）。
- 单 uvicorn worker、单宿主、单 SSH 隧道；内存限流/锁定，无法扩 worker；无压测/SLO（data-ops F-10）。
- 无仓库 LICENSE，893MB 数据集无来源/许可清单，Huatuo license 为空；SaMD/NMPA/互联网诊疗分类未处理（security P2-15 / data-ops F-15）。
- Analytics 只有事件计数，无漏斗/留存/转化；客户端可伪造任意事件与 props（data-ops F-13）。

### 6. 安全边界
- 导出/删除敏感操作只需 Bearer token，无二次认证/审计；JWT 在 localStorage 12h、无 CSP/HSTS；上传目录 755/图片 644（security P1-08/P2-10）。
- 上传信任客户端后缀/MIME，先读全量再查大小，无 magic-byte/EXIF/AV/重编码（security P2-10）。
- 用户名锁定可被用来定点锁死 admin；`AUTH_ENABLED=false` 是全局 admin 旁路（security P2-11/P2-13）。
- 聊天工具可直接 cancel/get 任意 order_id，绕过 REST 归属校验；MCP 无鉴权（security P2-14 / booking F10）。
- 审计缺登录、改密、导出、看图、挂号创建等动作；audit_log 详情本身是 PHI，所有 admin 可读（security P1-07）。

## 系统性根因

1. **没有临床安全负责人和可执行的临床规则库**：关键词表、DDI 表、危机脚本、报告阈值都没有来源/版本/签署人。
2. **没有真实业务状态机**：问诊、报告、挂号、支付、审核、随访都是“能走通一次”的流程，不是可恢复、可对账、可终止的状态机。
3. **没有“真实世界”边界**：医院 MCP、患者身份、支付、模型供应商、数据合规都停留在 mock/文案层。
4. **没有发布门禁**：评测不覆盖真实失败类型，CI 不跑质量阈值，监控/备份/迁移不构成生产控制。
5. **前后端按“页面能做出来”验收，而不是按“用户目标能否完成”验收**：这是“数据在、入口断；文案有、能力无”的根源。

## 建议的决策顺序（不是代码计划）

**第一优先（停止真实患者使用，或明确标注为演示）**
- 先把 DB/Redis 收回 loopback、换强口令/非超级用户；处理隐私/协议/第三方共享；修危机识别和红旗即时升级；修 DDI 假阴性；去掉自动补引用和“人工复核”假承诺。

**第二优先（真实试点前）**
- 挂号库存/订单状态机/退款改约/通知；证据相关度与来源分级；报告危急值；审核队列可见性；删除/审计/保留；管理后台双人复核/改密审计。
- 版本化迁移 + 真实监控 + 备份异地加密 + 盲测/引用/DDI/报告评测。

**第三优先（产品完善）**
- 会话历史、订单历史、时间线深链、用药提醒、错误四态、移动端/无障碍、分析漏斗、许可证/SaMD。

> 结论：当前版本适合“受控演示”，不适合直接承载真实患者数据或真实支付。P0 里任何一项单独发生都可能构成医疗安全/隐私/资金事故。
