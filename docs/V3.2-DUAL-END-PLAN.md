# 双端 + 真 HIS 整体方案

> 日期：2026-11-10（v3.2 起点）
> 对象：`smart_hospital_agent_v2`，线上 `hospital.kk.zhzepei.cn`，本地 OpenHIS V1.3（:18080）
> 定位：**一个 Agent 内核 + 两个角色域 + HIS 唯一事实源**
> 状态：方案稿，待决策项见第 10 节

---

## 0. 摘要与设计原则

当前项目是**单角色（患者端）**设计：五个平级功能页、13 个 MCP 工具全部是"患者/事务域"，
没有任何临床写工具、没有医生身份、没有签名审计。要接真实 HIS 并产生价值，必须补齐**医生端**。

### 五条硬原则

1. **HIS 是唯一事实源**：本地只存投影（projection）与草稿（draft），不允许出现第二份"真相"。
2. **AI 只读临床，写临床必须医生签名**：Agent 产出永远是草稿；签名权归医生本人 HIS 账号。
3. **一个内核，两个角色域**：同一套 Agent 运行时、工具、事实层；角色只决定"能看到什么、能做什么"。
4. **所有写操作幂等 + 可对账**：`idempotency_key` + `sync_outbox`；对账发现问题必须落 `reconciliation_finding`。
5. **每个承诺都要有对应 API 和验收用例**：页面上写了"人工复核/证据来源/家属授权"，就必须有落库和测试。

### 一图看懂

```text
                         ┌──────────────────────┐
     患者端（移动）      │  医生端（桌面工作台） │      运营/质控端
     解释 + 代办         │  摘要 + 草稿 + 签名   │      对账 + 审核 + 复盘
                         └──────────┬───────────┘
                                    │  JWT + 角色
                         ┌──────────▼───────────┐
                         │   Agent 内核（单循环）│  工具注册表 / 策略 / 审计
                         └──────────┬───────────┘
                                    │  MCP（JSON-RPC + X-Adapter-Scope）
                         ┌──────────▼───────────┐
                         │   HIS Adapter（:9101）│  投影同步 / 幂等 / 对账 / 只读池
                         └──────────┬───────────┘
                    ┌───────────────┼────────────────┐
              OpenHIS REST      OpenHIS 只读库    本地 PG（投影/草稿/审计）
```

## 1. 端（Ends）

| 端 | 用户 | 核心任务 | 形态 | 现状 |
|---|---|---|---|---|
| **患者端** | 患者 / 家属 | 看懂、挂号、缴费、随访 | 移动优先 Web/PWA，对话 + 卡片 + 任务 | **已有 ~90%** |
| **医生端** | 门诊医生 | 30 秒判读、写病历、开医嘱、签名 | 桌面三栏工作台，可嵌 HIS 侧栏 | **0，需新建** |
| **运营/质控端** | 医院运营 / 医务科 | 支付审核、对账、危机复盘、审计 | 桌面后台 | **有半成品**（现 `/admin`） |
| 收费/药房端 | 收费员 / 药师 | — | **不做**，用 HIS 原生界面 | — |

### 1.1 患者端（保留，收敛定位）

- 定位：**就医代理**——解释 + 导航 + 事务代办，**不做诊断**。
- 保留：首页任务中心、三步问诊、结果页 + 证据抽屉、报告解读、药管家、挂号缴费、健康时间线、家庭档案。
- 收敛：删除"AI 诊室"里任何"确诊/开药"暗示文案；把"人工复核"改成真实队列状态（见 4.3）。
- 成功指标：问诊完成率、报告解读后 7 天内就医率、挂号转化率。

### 1.2 医生端（新建，价值锚点）

**不是聊天窗**，是"诊前摘要 + 诊中按需 + 诊后文书"三段的**诊室副驾**：

| 区 | 内容 | 数据来源 |
|---|---|---|
| 左 | 患者 360：基本信息、过敏、既往、在用药物、本次预问诊、上次就诊 | HIS 只读 + 本地投影 |
| 中 | 病历编辑 / 医嘱 / 处方草稿 | 医生输入 + Agent 生成 |
| 右 | 证据（指南原文/相关度）、风险（相互作用/妊娠/危急值）、待办 | 检索 + 规则引擎 + HIS 检验 |

- **禁区**：不能自动签名、不能自动提交、不能跨患者查询。
- 成功指标：诊前摘要打开率、草稿采纳率、单次接诊节省时间、病历完整度。

### 1.3 运营/质控端（拆分现有后台）

- 支付/临床复核队列（HITL）
- 对账看板（`reconciliation_finding`：状态/金额/处方/就诊进度）
- 审计与危机复盘（谁看、谁采纳、谁签字）

## 2. 角色与权限域

### 2.1 六个域（替换现有 `SCOPES = {agent_read, service_write}`）

| 域 | 使用者 | 数据范围 | 可写对象 | 签名 |
|---|---|---|---|---|
| `patient_read` | 患者端 | 本人 + 本人家庭成员 | — | 否 |
| `patient_write` | 患者端 | 本人 + 家庭成员 | 建档、挂号、支付、取消、上传报告、consent | 否（事务型） |
| `clinician_read` | 医生端 | **本院/本科室当班患者** | — | 否 |
| `clinician_write` | 医生端 | 当班患者 | 接诊、诊断、医嘱、处方、诊毕 | **必须** |
| `ops_read` | 运营端 | 全量（脱敏） | — | 否 |
| `ops_write` | 运营端 | 审核/对账范围 | 审批、任务状态、finding 处理 | 二次确认 |

### 2.2 约束矩阵（验收必须覆盖）

| 场景 | 期望 |
|---|---|
| 患者 token 调 `clinician_*` | 403 `ADAPTER_SCOPE_DENIED` |
| 医生 A 调医生 B 的当班患者 | 404（不泄露存在性） |
| 患者端调任何临床写 | 403，且审计留痕 |
| `clinician_write` 缺签名/确认人 | 422，不落 HIS |
| 任何写操作重放同一 `idempotency_key` | 返回首次结果，HIS 侧记录数不变 |

### 2.3 医生身份与签名（关键设计）

- **方案 A（推荐）**：医生用**自己的 HIS 账号**登录医生端，adapter 以该 token 透传；
  "签名"就是 HIS 侧签名，`confirmed_by` = 医生工号，审计天然成立。
- **方案 B（兜底）**：服务账号 + `confirmed_by` 字段。**不能作为生产形态**——"谁签的字"无法证明。
- 无论 A/B：每条 Agent 建议都要记录 `seen_by / accepted / edited_ratio / signed_by`。

### 3.4 工具契约（统一）

```json
{
  "ok": true,
  "data": {},
  "error": {"code": "HIS_UNAVAILABLE", "message": "", "retryable": true},
  "meta": {"source": "openhis", "stale": false, "latency_ms": 0.0, "trace_id": ""}
}
```

规则：写工具必带 `idempotency_key` + `confirmed_by`；读工具允许 `stale=true`（投影过期）；
所有返回带 `trace_id`，可与审计日志对上。

## 5. 数据流与同步

### 5.1 读：HIS → 投影

```text
OpenHIS ──(轮询/游标)──▶ his_adapter.sync ──▶ 本地投影表 ──▶ 患者端 / 医生端
                          └─ 只读池直连 HIS 库（读已提交）做兜底与对账
```

现状：`sync_active_projections()` 是"逐条未结预约查 HIS"，`his_sync_cursor` 建了未用。
**M2 前必须改成游标增量**，否则数据量上来后同步会退化成全表扫。

### 5.2 写：草稿 → 签名 → HIS

```text
Agent 生成草稿（本地 draft 表，不落 HIS）
   └─▶ 医生编辑 / 确认
        └─▶ clinician_write 工具（携带医生 token + confirmed_by + idempotency_key）
             └─▶ OpenHIS 写入
                  └─▶ outbox 完成 → 投影回写 → 审计
```

### 5.3 对账（四类）

| 维度 | 本地 | HIS | 判定 |
|---|---|---|---|
| 状态 | projection.status | encounter.status | 不等 → finding |
| 金额 | projection.paid_amount | HIS 收费记录 | 不等 → finding |
| 处方 | prescription_map | 处方明细 | 缺行/多行 → finding |
| 进度 | visit.status | 就诊进度 | 倒退 → finding |

输出：`checked / findings / open_findings`，开放 finding 必须为 0 才允许发布。

## 6. 验收剧本（Acceptance Scenarios）

> 所有剧本在**真 OpenHIS**上跑；断言同时读 HIS 库（只读池）与本地投影，双源一致才算通过。
> 一条命令：`make accept-dual`（M3 交付），产出 JSON + Markdown 报告。

### A. 患者端（P-01 ~ P-08）

| ID | 场景 | 断言 |
|---|---|---|
| P-01 | 新患者建档 | HIS 生成唯一 patient_id；同一身份证再建 → 复用，不新增 |
| P-02 | 查询号源 | 只返回本人可挂科室；无号源明确提示 |
| P-03 | 挂号 | HIS 生成 encounter；本地投影状态 `quoted/awaiting_payment` |
| P-04 | 缴费 | HIS 收费成功；投影 `registered/paid`；金额一致 |
| P-05 | 重复缴费 | 同 idempotency → 返回首次结果，HIS 只 1 笔 |
| P-06 | 取消/退费 | HIS 退费成功；投影 `cancelled/refunded`；号源释放 |
| P-07 | 报告解读 | 无相关证据时明确"未覆盖"，不编造引用 |
| P-08 | 家庭档案 | 成员 A 的数据对成员 B 不可见 |

### B. 医生端（D-01 ~ D-08）

| ID | 场景 | 断言 |
|---|---|---|
| D-01 | 当日队列 | 与 HIS `current-day-encounter` 条数一致（误差 0） |
| D-02 | 患者 360 | 过敏/既往/用药与 HIS 一致；缺失显示"未记录"而非空 |
| D-03 | 诊前摘要 | 每条结论可回溯到来源（HIS 字段或证据 ID） |
| D-04 | 接诊 | HIS encounter 状态 → 在诊；投影同步 |
| D-05 | 诊断保存 | 落 HIS 且带医生 ID；未签名状态不可见给患者 |
| D-06 | 医嘱/处方签名 | 签名后 HIS 可见；缺签名 → 422 且不落库 |
| D-07 | 诊毕 | HIS → 诊毕；后续不可再改（只读） |
| D-08 | 跨科/跨患者 | 一律 404 |

### C. 双端闭环（E2E-01 ~ E2E-03）

| ID | 剧本 | 断言 |
|---|---|---|
| E2E-01 | 常规门诊全链路：预问诊 → 挂号 → 缴费 → 医生接诊 → 诊断/医嘱/处方签名 → 收费发药 → 患者端看到处方与解读 | HIS 8 个节点状态正确；双端看到同一 encounter；对账 findings=0 |
| E2E-02 | 退号退费：挂号未就诊 → 取消 → 退费 | 双端状态一致；号源可再挂 |
| E2E-03 | 并发抢号：50 并发抢同 1 号源 | 恰 1 单成功；49 单明确失败且无副作用 |

### D. 集成一致性（INT-01 ~ INT-06）

| ID | 场景 | 断言 |
|---|---|---|
| INT-01 | 幂等重放（10 次） | HIS 记录数不变 |
| INT-02 | 故障注入 500 / 超时 / 401 | 明确错误码 + 可重试标记；无半条数据 |
| INT-03 | 强制不一致 | 手工改 HIS 状态 → 轮询周期内产生 finding |
| INT-04 | 权限越界 | 患者 token 调 clinician_* → 403 |
| INT-05 | 审计完整 | 每条 agent 建议与每个签名都能查到人/时间/内容 |
| INT-06 | 数据隔离 | 仿真 tenant 与生产 tenant 互不可见 |

## 9. 风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| OpenHIS 业务接口无官方文档（Swagger 仅 flowable/test） | 医生站接口反推有成本 | 从前端 bundle 枚举 577 条路径 + 探针脚本 + 契约快照（锁 V1.3） |
| 医生身份与签名 | 签名不成立 → 整条链路没有合规价值 | 必须用医生本人 HIS 账号（方案 A） |
