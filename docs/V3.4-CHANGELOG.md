## 0. 维护规则（30 秒读完，硬约束）

1. **一次提交一条记录**，提交后 5 分钟内补记；漏记的改动视为"未完成"。
2. `commit` 必填真实 hash；还没提交的写 `未提交`，完成后改成 hash。
3. **屏范围用原型 ID**（`a-rules` / `p-prep` / `d-rx`），取自 `prototype/dual-end.html`，不要自造名字。
4. **动手前先登记「在途占用」**，完成后从占用区删掉、写进「变更记录」。**同一文件同一时间只能有一行占用**——这是防止互相覆盖的唯一机制。
5. **只写事实**：改了什么 / 验证命令与结果 / 风险与未做。不写计划、不写感想、不写"应该没问题"。
6. 校验命令（门禁会跑）：

```bash
python3 scripts/v34_changelog.py           # 人读
python3 scripts/v34_changelog.py --strict  # hash 不存在 / 屏 ID 非法 / 重复占用 → 非 0 退出
```

## 3. 事故与排障（RCA）

### 2026-11-11 · 建表中断：保留字 `window`
- **现象**：`asyncpg.exceptions.PostgresSyntaxError: syntax error at or near "window"`；应用启动被 `try/except` 吞掉，日志只留 `[startup] database init failed`，进程看似正常但**后续所有表都不存在**；`e2e_reset.py` 直接失败，Playwright 全线跑不起来。
- **根因**：新增表 `dispensing_progress` 用 `window` 做列名（Postgres 保留字），且 `init_schema()` 是整串语句顺序执行、无逐条容错。
- **修复**：列名加双引号，定义与查询两处同步。
- **教训**：
  1. 新增列名避开 `window / order / user / group / when / end / check / table` 等保留字，不确定就一律加双引号；
  2. 建表失败应让进程**启动失败**（fail fast），不要吞掉异常继续跑——否则"表不存在的 500"会伪装成业务 bug；
  3. 每波收尾要跑一次**从零建库**（事务内回滚即可），不要只在已有库上跑测试。
