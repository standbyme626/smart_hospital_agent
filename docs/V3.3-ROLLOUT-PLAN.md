# V3.3 全量上线计划

> 日期：2026-11-10
> 原则：**上线一个、接入一个；没接的显示占位，不装成能用。**
> 演示站：https://hospital.kk.zhzepei.cn/preview/
> 真实站：https://hospital.kk.zhzepei.cn/（v3.1，不动）

---

## 0. 目标

把 61 屏原型，按页面切片推进到"真实可用"：

1. 每页接真实 API 后才允许从 `/preview` 升级到真实路径；
2. 未接入的模块明确标注「演示 / 未接入」，不产生真实挂号、支付、通知；
3. 每页可单独回滚；
4. 每页至少一条验收用例（对应 26 条验收剧本）。

## 2. 完成定义（DoD）

一页算"上线"，必须同时满足：

- [ ] 真实接口，无 mock 数据进入真实路径
- [ ] 六种状态：空 / 加载 / 错误 / 无权限 / 超时 / 断网
- [ ] 权限：scope + 行级归属校验
- [ ] 审计：谁看、谁操作、trace_id
- [ ] 验收用例 ≥ 1 条，且有证据
- [ ] 页面上有「真实 / 演示」数据源标签
- [ ] 可回滚（路由或开关）

## 4. 六周节奏（2–3 人并行）

| 周 | 交付 |
|---|---|
| W1 | S1 + S2（登录、首页、问诊真实化） |
| W2 | S3 + S4 + S5（报告、药、挂号支付） |
| W3 | S6 + S7（通知、随访） |

每周末出一次「上线清单」：哪些页从 /preview 升到真实路径、哪些还是占位。

## 5. 上线流程（每页）

1. 开分支 → 接真实 API → 补六态 → 补权限与审计；
2. 本地跑测试 + 手动走查；
3. 部署到 `/preview` 验证；
4. 验收用例通过 → 加 feature flag → 升级到真实路径；
5. 观察 24h（错误率、耗时、审计）→ 去掉占位标签。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 医生签名依赖 HIS 账号 | S9 阻塞 | 先与院方要测试医生账号 |

| 合规（真实患者数据） | 上线范围 | 试点期只用院内测试患者 |
| 单机部署 | 可用性 | 试点期接受，正式期再扩 |
