# V3.4 全量真实上线计划

> 日期：2026-11-10
> 目标：**61 屏原型全部真实上线**——真实接口、真实数据库、真实权限与审计、可回归验收；不再有“演示页”。
> 现状：17 屏已真上线、5 屏部分、39 屏未上线（其中管理端 4 屏属于设计/内部工具，见 §2）。

---

## 1. “真实上线”的定义（每屏必须满足）

- [ ] 真实 API（无前端 mock；读写落库）
- [ ] 真实数据源（本地 PG 或 OpenHIS 实例）
- [ ] 权限校验（角色 + 归属 + 行级）
- [ ] 六态齐全（空 / 加载 / 错误 / 无权限 / 超时 / 断网）
- [ ] 审计留痕（谁看、谁操作、trace_id）
- [ ] 至少 1 条自动化验收（pytest 或 Playwright E2E）
- [ ] 可回滚（功能开关或路由级）

> **外部系统口径**：本地部署的 OpenHIS V1.3 视为“真实医院系统”（真实表结构与接口）。凡需要院方凭据或外部专网的（医保实时结算、短信运营商、真实医院生产库），实现**真实适配器 + 开关**，并在页面标注“待院方开通”，不伪造数据。

## 3. 外部依赖与决策（开工前必须拍板）

| 依赖 | 现状 | 决策建议 |
|---|---|---|
| 医生 HIS 账号与签名透传 | 无 | **阻塞医嘱/处方/诊毕**；先草稿 + 门禁，拿到测试账号后打通 receive-encounter / save-advice / sign-advice |
| 医保结算 | OpenHIS 有 yb_* 表与接口，无医保专网 | 做**只读**结算快照与对账；“实时结算”标注待院方开通 |
| 短信 / 微信通道 | 仅有站内信 | 接阿里云短信 / 微信服务号（需账号）；未开通前站内兜底 |
| 排班 / 停诊 | HIS 无排班表 | **平台自建排班**（真实落库），与 HIS 当日号源对齐 |
| 药师审方 | OpenHIS 有审核记录表 | 只读展示 + 平台提醒；不替代药师 |
| 真实生产医院库 | 无 | 本地 OpenHIS 作为验收目标；生产对接单独立项 |

### 3.1 模拟策略：在 HIS 侧造真实数据，不 mock 自己的后端

原则：**我们的接口、权限、审计、页面全部真实；模拟只发生在“被接入的那一端”**——在本地 OpenHIS 里创建真实记录，或用驱动模式替代外部通道。

| 卡点 | 模拟方式（HIS 侧造真实数据） | 验收标准 | 页面标注 |
|---|---|---|---|
| 医生签名写 HIS | 在 OpenHIS 建**测试医生账号**（sys_user + practitioner），走真实 `receive-encounter` / `save-advice` / `sign-advice`；签名在 HIS 侧可查 | HIS 里能看到就诊、医嘱与签名人；我方审计可追溯 | 「本地 HIS 测试医生」 |
| 医保实时结算 | 向 OpenHIS 的 `yb_*` 结算表写入测试结算（统筹/个账/自付），我方只读并做对账 | 金额与 HIS 一致、对账 0 差异 | 「本地模拟医保结算 · 非实时联网」 |
| 短信 / 微信 | 通道层做 `SMS_MODE=mock` 驱动：真实模板与重试逻辑，发送记录落 `notification_deliveries`；接真实运营商只需换驱动 | 模板渲染、重试、退订、审计齐全；记录可查 | 「模拟通道（未产生真实短信）」 |
| 真实生产医院库 | 本地 OpenHIS 即“真实系统”；用种子脚本灌测试数据（21 科室、医生、号源、患者、就诊） | 全链路真实接口跑通；数据量可复现 | 「本地 HIS 实例 · 测试数据」 |

补充约束：
- 造数优先走 HIS 自己的 API，只有主数据（科室/医生/号源）才允许直接写库；
- 测试患者用统一前缀（如 `T-`）或独立租户，避免混入真实患者；
- 生产切换时只换驱动与凭据，不改业务代码；
- 页面必须显示数据来源与“测试数据”标识，不能伪装成生产数据。

## 5. 六个波次

### Wave A · 基础设施（2–3 天）
- 权限依赖 require_clinician / require_ops / require_admin（已具备）
- 六态组件与 E2E 基座（已具备）
- 新增：编号化数据库迁移 + 回滚脚本；统一审计写入 helper
- 出口：迁移可重复执行、审计字段齐全

### Wave B · 患者端补齐（5–6 天）
| 屏 | 实现 | 验收 |
|---|---|---|
| 就诊准备 | previsit_forms + 提交 API + 医生端摘要读取 | 提交后医生 360 可见 |
| 取药进度 | 同步 OpenHIS dispensing-order 只读状态 | 四步流转 |
| 医保结算 | insurance_settlements 只读快照 | 金额与 HIS 一致 |
| 就诊指引 / 叫号 | queue_tickets + 状态机 | 叫号与等待时间 |
| 客服 / 投诉 | feedback_tickets | 提交→受理→答复 |
| 移动端 PWA | manifest + service worker + 移动导航 | 可安装 |
| 家庭授权矩阵 | consent_scopes | 撤回立即生效 |

### Wave C · 医生端补齐（10–12 天）
| 屏 | 实现 | 依赖 |
|---|---|---|
| 结构化病历 | clinical_notes（主诉/现病史/查体/诊断） | 无 |
| 医嘱 / 处方 | clinical_orders 草稿 → 签名门禁 → HIS | 医生 HIS 账号 |
| 检验 / 检查 | lab_results 只读同步 + 异常标记 | HIS 接口 |
| 诊毕 / 随访 | 诊毕状态 + 随访计划 | 医嘱链路 |
| 药师审方 | HIS 审核记录只读 | HIS 接口 |
| 我的排班 | schedules 平台自建 | 无 |
| 移动查房 / 待办 | 复用队列与待办 API | 无 |
| 会诊 / 转诊 | consultations 工单 | 无 |
| 文书打印 | 打印模板 + print_jobs | 无 |

### Wave D · 运营端补齐（5–6 天）
| 屏 | 实现 |
|---|---|
| 支付异常逐笔 | 待审详情 + 批准/拒绝 + 双人复核 |

| 危机事件 | crisis_events + 处置/复盘 |
| 通知记录 | notification_deliveries + 重试 |

### Wave E · 管理端补齐（15–18 天）
配置总览、HIS 接入、Agent 配置、Prompt 管理、知识库策略、未命中问题、语料与索引、RAG 全链路、模型网关、规则库、通知模板、检索调试、会话回放、验证自测、配置审计、权限与账号、多院区、实验与灰度。
- 验证自测优先（把 26 条剧本落成可执行）
- 实验与灰度与 Prompt / 规则版本共用开关

### Wave F · 总验收与发布（3–4 天）
- 26 条剧本全绿；E2E 覆盖每个入口关键路径
- 安全加固：入口 IP 白名单、限流、审计抽查
- 文档与版本号；发布与回滚演练

---

## 7. 每波出口标准
- 该波全部屏：pytest + 至少 1 条 E2E
- 数据一致性：本地投影 vs HIS 只读库对账 0 差异
- 安全：越权 403、未登录 401、审计可查
- README 进度表同步更新
- 回滚：开关关闭后页面显示“未开放”，不白屏

---

## 8. 风险
| 风险 | 影响 | 缓解 |
|---|---|---|
| 医生 HIS 账号迟迟不到 | 医嘱/处方/诊毕无法真写 | 草稿先行，签名开关默认关 |
| 医保/短信外部通道未开通 | 相关屏只能只读/站内 | 适配器 + 开关 + 页面标注 |
| 管理端 18 屏工作量大 | 排期膨胀 | 拆三批：配置类 / 知识类 / 观测类 |
| 真实数据合规 | 试点范围受限 | 只用测试患者；生产数据需审批 |
