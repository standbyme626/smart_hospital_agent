# smart_hospital_agent v3.1 验收表

> 版本：2026-11-09  
> 目标：把现有“可演示”收口为“真实可用”：前端每个动作都有真实 API/数据支撑，刷新不丢、换账号不串、删除可生效、支付必须人工确认。  
> 配套计划：`docs/V3.1-PLAN.md`  
> 范围外：真实医院 MCP 接入（需院方接口与凭据，列入 v3.2）、自规划/多 Agent、临床盲测、多租户/SaaS、自注册、医生工作台、药盒识别、陪诊。

## 优先级

- **P0**：不满足则不能称为 v3.1，不允许发布。
- **P1**：可用性/安全加固，允许在发布后一个迭代内补齐，但必须在计划中排期。
- **P2**：后续增强，不计入 v3.1 门禁。

## 发布门禁

发布前必须同时满足：

1. AC-01/02/03/10/11/13/14/19/20/23/24/25/27/30/35/36/38/39 全绿。
2. `backend/.venv/bin/pytest -q` 全绿；`ruff check` 全绿；`frontend npm run build` 通过。
3. 构建产物与文档扫描无真实凭据。
4. 线上 `/api/health` 200，Kuma 监控正常。
5. 备份已跑一次，恢复演练已记录。
6. 轮换 admin/patient 密码，删除前端与文档中的旧 token。
