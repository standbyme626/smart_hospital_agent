| 状态 | 含义 | 判定 |
|---|---|---|

| `GAP` | 未上线 | 无页面、无接口 |

## 7. 管理端 Wave E 实施笔记（2026-11-11）

### 7.1 已上线：配置类 4 屏（a-rules / a-notify / a-prompt / a-agent）

一份底座撑四屏，避免每个配置屏各写一套版本逻辑：

| 组件 | 文件 | 内容 |
|---|---|---|
| 表 | `backend/app/schema_admin.py` | `config_entries`（kind/key/draft/published/version/enabled + 发布人时间）、`config_history`（每次发布与回滚的不可变值）；幂等建表 + 12 条默认条目 |
| 接口 | `backend/app/routes_admin_config.py` | 9 个端点：kinds / changes / list / get / PUT 草稿 / publish / rollback / enabled / history / 模板 preview；全部 `require_admin`，写操作落 `audit_log`（带 request_id） |
| 客户端 | `frontend/lib/api-admin-config.ts` | 独立客户端，不动 `lib/api.ts`，管理端迭代不会与其他端冲突 |
| 页面 | `frontend/app/platform/config/page.tsx` | 三栏：种类 Tab → 条目列表 → 草稿编辑 + 生效值 + 版本历史（含「回滚到此版」）；通知模板带变量预览与缺失变量提示 |
| 测试 | `backend/tests/test_admin_config.py`、`frontend/e2e/s13-admin-config.spec.ts` | 8 条 pytest（权限 / 草稿发布分离 / 版本递增 / 回滚 / 停用 / 校验 / 预览 / 审计）+ 3 条 E2E（患者 403、新建→发布→历史、模板预览） |

语义要点（后续屏沿用）：
- **草稿与生效分离**：PUT 只改 draft，不改变线上行为；publish 才 version+1 并写 history；
- **回滚产生新版本号**，不覆盖历史，时间线永远可追；
- **停用后 `effective` 为空**，页面显示「未启用」，避免"停用了还在生效"；
- 重复发布同内容返回 409，避免刷版本号。
