状态口径（比计划文档 §2 更严，按"页面 + 接口 + 测试"三证折算）：

| 状态 | 含义 | 判定 |
|---|---|---|
| `LIVE` | 真实上线 | 页面 + API + 至少 1 条自动化测试，三证齐全 |
| `PARTIAL` | 部分 | 有页面或接口，但缺测试 / 缺写链路 / 只有只读 |
| `DOING` | 进行中 | 本工作树有未提交改动或新接口，尚未接入页面 |
| `TOOL` | 内部工具页 | 设计/规范类，不要求真实数据 |
| `GAP` | 未上线 | 无页面、无接口 |

## 2. 统计与口径差异（2026-11-11 首版）

| 口径 | 已上线 | 部分 | 进行中 | 内部工具 | 未上线 |
|---|---:|---:|---:|---:|---:|
| 计划文档 §2 自述 | 17 | 5 | - | 4 | 39 |
| **台账实测** | **21** | **11** | **1** | **2** | **26** |

差异原因（不是进度变快，是口径不同）：
1. 计划按"页面做完"算上线；台账要求**页面 + 接口 + 测试三证**，所以 `o-audit`/`o-analysis`/`a-model` 这类"有接口没屏"的从"已上线"降级为 `PARTIAL`；
2. 计划把 `p-guide`（就诊指引）、`p-auth` 计入未上线，实测 `/api/v1/booking/appointments/{id}/guide` 与登录页均已存在 → 升为 `LIVE`；
3. 计划把管理端 4 屏"设计/内部工具"计入未上线，台账单列 `TOOL`（实际原型里只有 `a-flow`/`a-states` 两屏属此列）。

> 结论：**真实缺口是 26 屏 GAP + 11 屏 PARTIAL**，管理端占 16（GAP 10 + PARTIAL 6），是排期最大风险，与计划 §8 判断一致。

## 3. 文件归属（并发防覆盖）

> 当前三线共用一个工作树，`routes.py`(≈3000 行) / `db.py` / `api.ts` 是**高危单点**：
> 两人同时编辑同一文件不是"git 冲突"，而是**直接互相覆盖**（后写者赢），且 `edit` 的 `old_string` 会失配。
> 2026-11-11 14:39–14:44 已出现 B 线在改这三个文件，任何人此时动同一区块都会丢代码。

| 文件 | 归属 | 规则 |
|---|---|---|
| `backend/app/db.py` | **A（基础设施）独占** | 表定义只由 A 追加；B/C 把建表 SQL 写到 `docs/V3.4-SCHEMA-REQUESTS.md` 由 A 批量落库 |
| `backend/app/routes.py` | **待拆分**（见 §4） | 拆分完成前：谁的波次谁独占，其他人先做前端/测试 |
| `backend/app/routes_patient.py` 等 | B / C / D / E 各一 | 拆分后按端一人一文件，互不冲突 |
| `frontend/lib/api.ts` | **待拆分** | 拆成 `api-patient.ts`/`api-clinician.ts`/`api-ops.ts`/`api-admin.ts`，`api.ts` 只 re-export |
| `frontend/app/<端>/page.tsx` | 一线一页 | 患者页 B、clinician C、ops+platform+admin D/E |
| `README.md` / 本台账 | **整合者独占** | 只有整合者（我）在波次收尾时更新 |
| `backend/tests/test_*.py` | 谁写功能谁写测试 | 新文件名按屏 ID 命名，避免撞名 |
| `docs/` 规划类 | 一人一文件 | 已存在文件不要多人改同一段 |

## 4. 并行协议（建议立即执行）

1. **一人一分支**：`wave-a` / `wave-b` / `wave-c` / `wave-d` / `wave-e`，用 `git worktree` 各自独立目录，合并顺序 A→B→C→D→E；当前"同一工作树三线共写"必须停掉或至少串行。
2. **一屏一提交**：`feat(p-prep): 预问诊提交 + 医生 360 摘要`，提交信息带屏 ID —— 台账和 `git log` 才能对账。
3. **拆 monolith 是本波最高优先**：`routes.py` 拆四个分文件（改动只是把装饰器搬走 + `include_router`），**一次性解除后续 6 周的冲突**，约 0.5 天。
4. **每次提交前跑**：`python3 scripts/v34_status.py --strict`，证据不足直接失败，避免"自述上线"。
5. **合并后由整合者统一更新** README 进度表 + 本台账第 2 节统计。
